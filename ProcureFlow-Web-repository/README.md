# ProcureFlow Web 1.0

Самостоятельная веб-версия планирования закупок по кейсу HACKALEM AI / Электрокомплект. Исходные Excel обрабатываются в браузере. Сервер отдаёт только файлы интерфейса. Этот репозиторий можно целиком разместить в отдельном GitHub-репозитории `procureflow-web`.

## Запуск на компьютере

1. Установите [Node.js 24 LTS](https://nodejs.org/). Минимум — Node.js 22.12.
2. Распакуйте архив и откройте терминал в папке, содержащей `package.json`.
3. Выполните:

```sh
npm start
```

4. Откройте **http://127.0.0.1:8000/** в актуальном Chrome или Edge. Терминал оставьте открытым. Остановка — Ctrl+C.

На Windows можно вместо команды дважды щёлкнуть `START-WEB.cmd`.
Веб-репозиторий не имеет npm-зависимостей: `npm install` для запуска не требуется. Python, Electron и сборка EXE не нужны.
Если порт занят: `npm start -- --port 8001`, затем откройте адрес с портом 8001.

Используйте локальный HTTP по 127.0.0.1/localhost либо HTTPS. Открытие файла двойным щелчком и HTTP по сетевому IP не являются основным режимом: фоновые задачи и Web Crypto зависят от контекста безопасности браузера.

## Загрузка в GitHub и публикация сайта

1. Создайте отдельный репозиторий **procureflow-web**. Для бесплатного GitHub Pages он должен быть публичным.
2. Загрузите **содержимое** этой папки в корень: `index.html`, `assets`, `scripts`, `tests`, `package.json`, `package-lock.json`, `.github`, `.gitignore`, `.nojekyll` и документы. Не загружайте ZIP как один файл и не создавайте лишнюю внешнюю папку.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Web checks and GitHub Pages → Run workflow** на основной ветке `main` (либо `master`).
5. После успешного выполнения адрес появится в **Settings → Pages** и в задании `deploy`. Обычно это `https://ВАШ-ЛОГИН.github.io/procureflow-web/`.

Workflow сначала запускает тесты и собирает `_site/`. На сайт попадают только 12 разрешённых публичных файлов. Публикация выполняется только с основной ветки; pull request проверяется без публикации. Все ссылки относительные, поэтому любое имя репозитория поддерживается.

Если используете Git вместо загрузки через сайт, выполните в этой папке (подставьте свой URL; целевой репозиторий должен быть пустым):

```sh
git init -b main
git add .
git commit -m "Initial ProcureFlow Web"
git remote add origin https://github.com/ВАШ-ЛОГИН/procureflow-web.git
git push -u origin main
```

Не загружайте коммерческие XLSX/CSV/ZIP, проекты `.pfproject`, пароли или ключи. `.gitignore` исключает типовые файлы данных при работе через Git; загрузка через сайт GitHub требует ручного выбора исходников.

Официальная инструкция: [GitHub Pages с собственным workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Работа с приложением

1. На странице «Загрузка данных» выберите свои XLSX/CSV/ZIP либо скачайте встроенный шаблон.
2. Проверьте источники, остатки, дату среза, поставщиков и склады. Укажите сроки поставки и параметры расчёта.
3. Изучите рекомендации и обоснования, при необходимости уточните данные товара и количество.
4. Утвердите заказ с указанием ответственного и выгрузите XLSX/CSV для 1С. Автоматической отправки нет.
5. Перед закрытием нажмите «Сохранить проект». Браузер скачает `.pfproject`; при следующем запуске нажмите «Открыть». Автосохранения нет.

Формат проекта совместим с Windows-версией 1.0. После открытия заказа требуется повторное утверждение.
Методология, форматы входных данных, приватность и ограничения описаны в [docs/METHODOLOGY.md](docs/METHODOLOGY.md).
Универсальный экспорт для 1С требует сопоставления колонок и проверки в тестовой базе компании.

## Проверки и сборка

```sh
npm ci
npm test
npm run check:offline
npm run build
```

`_site/` — готовый сайт для любого HTTPS-хостинга. Только его содержимое следует публиковать.
`npm run start:pages` проверяет локальный запуск по адресу `http://127.0.0.1:8000/procureflow-web/`.
Сервер слушает только 127.0.0.1, не принимает загрузки и не раздаёт документы, тесты или произвольные файлы из репозитория.

## Независимость от Windows

Это отдельный репозиторий с именем npm-пакета `procureflow-web`, собственными командами и workflow Pages. Windows-версия находится в отдельном репозитории `procureflow-windows`, который собирает EXE.
Связи через соседние папки, submodule и общие node_modules отсутствуют. Общие алгоритмы скопированы в оба репозитория. Исправления расчёта и формата проекта в дальнейшем нужно переносить в обе версии и проверять тестами.
Загрузка сайта с GitHub Pages требует интернета. Для автономного запуска используйте эту папку и локальный сервер. Service Worker и гарантированный офлайн-кэш сайта не реализованы.

## Структура

- `index.html`, `assets/` — интерфейс, импорт, расчёт, проекты и экспорт.
- `scripts/serve.cjs` — локальный сервер.
- `scripts/build-web.cjs`, `scripts/site-files.cjs` — сборка разрешённых публичных файлов.
- `tests/` — расчётные тесты, проекты, критерии ТЗ, HTTP и упаковка.
- `.github/workflows/pages.yml` — проверка и публикация на GitHub Pages.
