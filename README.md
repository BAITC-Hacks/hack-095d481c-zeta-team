# ProcureFlow — Web и Windows

## Что решает продукт

Приложение для расчёта заказов поставщикам по кейсу HACKALEM AI / ТОО «Электрокомплект». Обрабатывает историю продаж, остатки, товары в пути, сезонность, рост спроса, периоды отсутствия товара и разовые крупные продажи. Результат — рекомендации с объяснениями, проверкой менеджером и экспортом.

Обе версии находятся в **одном репозитории**, используют одинаковые расчёты и поддерживают **қазақша, русский и English**.

Основной пользователь — менеджер отдела закупа. ProcureFlow помогает свести выгрузки продаж и остатков в один расчёт, определить потребность в пополнении и проверить её до оформления заказа. Сезонность, устойчивый рост и упущенный спрос при отсутствии товара учитываются отдельно; разовые крупные покупки, в том числе одного клиента, исключаются из оценки регулярного спроса.

**Вход:** история продаж, обезличенные клиентские идентификаторы, остатки по складам, периоды stockout, товары в пути, категории, сроки поставщиков и материальная ведомость из 1С. **Выход:** рекомендации по артикулам, сгруппированные по поставщикам, с количеством, риском дефицита и обоснованием. Менеджер корректирует и утверждает заказ, затем явно выгружает файл.

Цель продукта — уменьшить избыток запасов, дефицит и время ручного расчёта в Excel. Фактический экономический эффект нужно оценить на истории и в пилоте компании.

## Как запустить

Выберите вариант в таблице. Пошаговые команды приведены ниже: [Web на компьютере](#запуск-web-на-компьютере), [Windows из исходников](#запуск-windows-из-исходников), [сборка Windows EXE](#сборка-windows-exe). Готовый Portable EXE запускается двойным щелчком без установки Node.js.

### Какую версию выбрать

| Задача | Что выбрать | Как открыть |
| --- | --- | --- |
| Быстро открыть приложение по ссылке, работать на разных ОС | **Web — main-web** | Опубликованный сайт GitHub Pages |
| Запустить веб локально на своём компьютере | **Web — main-web** | START-WEB.cmd или npm start |
| Работать в отдельном окне Windows без доступа к сайту | **Windows — main-windows** | Portable EXE или установщик Setup |
| Изменять код или собирать Windows-приложение | **main-windows** | Node.js 24, npm ci, npm start |

Расчёт и обработка загруженных таблиц выполняются на устройстве. У веб-версии нет серверной базы и учётной записи. Для открытия опубликованного сайта требуется интернет; для надёжной работы без интернета используйте локальный веб-сервер или готовое Windows-приложение.

Проекты **.pfproject** совместимы между версиями. Для переноса сохраните файл проекта в одной версии и откройте его в другой. Автоматической синхронизации нет. После открытия проекта заказы нужно утвердить заново.

**main-web и main-windows — папки, а не ветки Git.** Репозиторий использует общую ветку main или master. Настройки GitHub Actions находятся в корневой папке .github: GitHub не запускает workflows из вложенных main-web/.github или main-windows/.github.

У каждой версии отдельный package.json и свои зависимости. Команды npm выполняются внутри выбранной папки. Исходники, рабочие данные и результаты сборки не смешиваются: веб собирается в main-web/_site, Windows — в main-windows/dist.

## Выбор языка

В списке языка приложения выберите **Қазақша**, **Русский** или **English**. Переключение не перезагружает страницу и сохраняет текущие данные, ручные количества и утверждения заказов. Выбор языка запоминается на устройстве отдельно от рабочего проекта.

Переводится интерфейс приложения. Наименования товаров, поставщиков, складов и другие значения из ваших файлов сохраняются в исходном виде. Обычные заголовки и обоснования в экспортируемых отчётах используют выбранный язык. Структура входных шаблонов и настраиваемые названия колонок обмена с 1С не меняются при выборе языка.

## Запуск Web на компьютере

Установите **Node.js 24** вместе с npm. Откройте PowerShell в корне скачанного репозитория:

~~~powershell
cd main-web
npm.cmd start
~~~

Откройте адрес **http://127.0.0.1:8000/**. Держите окно сервера открытым; для завершения нажмите Ctrl+C. Можно вместо команд дважды щёлкнуть **main-web/START-WEB.cmd**.

На macOS/Linux используйте npm вместо npm.cmd. У веб-версии нет внешних npm-зависимостей для запуска. Открывайте её через локальный HTTP-сервер, чтобы работали фоновые вычисления и браузерные механизмы защиты.

## Запуск Windows из исходников

Нужны **Windows x64 и Node.js 24**. В новом окне PowerShell из корня репозитория:

~~~powershell
cd main-windows
npm.cmd ci
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm.cmd start
~~~

При первой установке зависимостей и первом запуске нужен интернет для скачивания Electron. Для повторного запуска достаточно npm.cmd start. После изменения package-lock.json снова выполните npm.cmd ci.

Альтернатива — двойной щелчок по **main-windows/START-WINDOWS.cmd**. Он устанавливает зависимости при их отсутствии и открывает приложение.

## Сборка Windows EXE

В папке **main-windows** выполните:

~~~powershell
npm.cmd ci
npm.cmd test
npm.cmd run check:offline
npm.cmd run dist:win
~~~

Или запустите **BUILD-WINDOWS.cmd**. В main-windows/dist появятся:

- **ProcureFlow-Portable-…-x64.exe** — запуск без установки.
- **ProcureFlow-Setup-…-x64.exe** — установщик для текущего пользователя.

Для готового EXE Node.js не нужен. Приложение работает локально без интернета. Сертификат подписи Windows в этом репозитории не настроен; сборки будут без цифровой подписи издателя.

## Какие технологии используются

| Компонент | Технологии и назначение |
| --- | --- |
| Интерфейс обеих версий | HTML5, CSS и JavaScript без UI-фреймворка; локальные словари русского, казахского и английского языков |
| Web | Статический сайт; локальный HTTP-сервер на встроенном модуле Node.js; публикация через GitHub Pages |
| Windows | Electron 44.4.5; electron-builder 26.16.1 собирает Portable EXE и установщик NSIS для Windows x64 |
| Расчёт | Собственный алгоритм на JavaScript: медиана/MAD для выбросов, месячная сезонность, тренд, восстановление stockout, учёт остатков и своевременных поставок, минимальной партии и кратности |
| Импорт и экспорт | Собственный модуль XLSX/CSV/ZIP; браузерные File/Blob, DOMParser и DecompressionStream; Web Worker для фоновой обработки импорта |
| Данные и приватность | Локальные JSON-проекты .pfproject; Web Crypto HMAC-SHA256 для распознанных клиентских идентификаторов; localStorage для выбора языка |
| Проверки и сборка | Node.js, npm и закреплённые package-lock.json; проверки расчёта и безопасности, сценарии интерфейса в Electron; GitHub Actions |

Для работы с исходниками рекомендуется **Node.js 24**; package.json допускает версии от 22.12.0. Серверной базы данных и внешних сервисов для расчёта нет. Прогноз строится по описанным статистическим правилам; внешняя языковая модель или обученная нейросеть не используются.

## Как загрузить один репозиторий в GitHub

Создайте пустой репозиторий, например **procureflow**. Распакуйте подготовленный архив исходников и загрузите **его содержимое**, включая скрытую .github. На главной странице репозитория должны быть видны README.md, LICENSE, main-web и main-windows.

При использовании Git откройте терминал в корне проекта:

~~~powershell
git init
git branch -M main
git add .
git status
git commit -m "Add ProcureFlow Web and Windows"
git remote add origin https://github.com/YOUR_LOGIN/procureflow.git
git push -u origin main
~~~

Замените YOUR_LOGIN своим именем GitHub. Проверьте список после git status: коммерческие выгрузки, .pfproject, node_modules, _site и dist не должны попасть в коммит. .gitignore уже исключает их.

### Публикация Web

1. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Откройте **Actions → Web checks and GitHub Pages → Run workflow** и выберите основную ветку main или master.
3. Дождитесь успешного завершения. Ссылка на сайт появится в **Settings → Pages** и в окружении **github-pages**.

Workflow проверяет main-web, создаёт main-web/_site и публикует только его содержимое. На сайте приложение открывается по адресу вида **https://YOUR_LOGIN.github.io/procureflow/**, без /main-web/ в конце. Исходники Windows, тесты и рабочие файлы не входят в сайт.

При последующих изменениях публикация выполняется из основной ветки репозитория. В pull request запускаются проверки без публикации. Возможность Pages зависит от настроек и тарифа GitHub. [Официальная инструкция GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### Получение Windows EXE через GitHub

1. Откройте **Actions → Build Windows EXE**.
2. Выберите успешный запуск или нажмите **Run workflow**.
3. В завершённом запуске откройте **Artifacts → ProcureFlow-Windows-x64**.
4. Распакуйте скачанный архив и выберите Portable либо Setup.

Workflow запускается при изменениях Windows-версии в main/master, pull request и вручную. Он устанавливает закреплённые зависимости в main-windows, запускает проверки, собирает EXE и проверяет упакованное приложение. Артефакт содержит Portable, Setup, SHA256SUMS.txt, отчёт проверки и lock-файл зависимостей. Срок хранения — 14 дней; затем сборку можно повторить. Автоматическое создание GitHub Release не настроено.

## Первый расчёт и экспорт

1. Откройте демо или загрузите XLSX/CSV/ZIP на странице загрузки данных. Коммерческие тестовые файлы не входят в репозиторий.
2. Проверьте распознанные источники, дату среза и ошибки данных. В параметрах укажите сроки поставщиков, склад, цикл заказа, запас и плановый рост.
3. Откройте рекомендации и карточку артикула: там показаны формула, сезонность, тренд, исключённые продажи и компенсация отсутствия товара.
4. Уточните неизвестные остатки и при необходимости измените количество с учётом минимальной партии и кратности.
5. В разделе поставщиков проверьте заказ, укажите ответственного и подтвердите проверку. Экспорт выполняется по действию пользователя; приложение само не отправляет заказ поставщику.
6. Сохраните проект вручную, чтобы продолжить позже. Автосохранения рабочего проекта нет.

Для универсальной конфигурации **1С** предусмотрен XLSX/CSV-экспорт утверждённых положительных количеств. Укажите организацию, склад и сопоставьте названия колонок с обработкой загрузки вашей базы. CSV использует UTF-8 с BOM и разделитель «;», XLSX сохраняет коды текстом, количества числами.

Универсальный формат обмена не означает готовую интеграцию с любой базой 1С. Перед рабочим использованием проверьте загрузку в тестовой базе. [Методология расчёта, исключение выбросов и входной шаблон](main-web/docs/METHODOLOGY.md).

## Как проверить решение

### Ручная проверка для демонстрации и приёмки

Пройдите сценарий в каждой версии на синтетических данных. Коммерческие архивы для него не нужны. Названия кнопок ниже указаны для русского интерфейса; действие «Очистить» выполняйте только в тестовом проекте.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Запустите приложение и выберите «Демоданные» или «Открыть демо» | Появляются 42 товарные позиции и рекомендации без ошибок расчёта |
| 2 | Переключите Русский → Қазақша → English, затем вернитесь к русскому | Интерфейс и обоснования переводятся; артикулы, исходные названия и количества не меняются; выбранный язык сохраняется после повторного запуска |
| 3 | Откройте рекомендации, «Почему?» у товара и раздел поставщиков | Карточка показывает спрос, запас, остаток, учтённые поставки, округление и объяснение; заказы можно посмотреть по поставщику |
| 4 | У демотовара с положительным заказом измените подтверждённый остаток на 1000000 и нажмите «Сохранить данные и пересчитать» | Рекомендация для этого товара становится нулевой: большой доступный остаток покрывает потребность |
| 5 | На странице загрузки нажмите «Скачать шаблон», очистите тестовые данные и загрузите полученный XLSX | Распознаются 2 товара и 2 поставщика; видны источники продаж, остатков, поставок, сезонности и stockout |
| 6 | Проверьте дату среза и параметры. При необходимости скорректируйте положительное количество с учётом минимальной партии и кратности; затем утвердите заказ поставщика | Для утверждения нужны ответственный и подтверждение проверки; в журнале появляется действие |
| 7 | Выполните явный экспорт утверждённого заказа в XLSX/CSV для 1С, указав организацию, склад и колонки | Скачивается файл с утверждёнными положительными количествами; артикулы и количества совпадают с заказом; автоматической отправки поставщику нет |
| 8 | Сохраните .pfproject и откройте его в другой версии приложения | Данные, параметры и ручные количества восстанавливаются; для дальнейшего экспорта заказа требуется повторное утверждение |

Файл для 1С сначала загрузите в **тестовую базу** через используемую в компании обработку. Проверьте сопоставление кодов номенклатуры, склада, поставщика, единиц и количества. Без этой проверки совместимость с конкретной базой не считается подтверждённой.

### Проверка обязательных требований ТЗ

Ручной сценарий проверяет работу менеджера. Поведение алгоритма проверяют воспроизводимые синтетические наборы в [тестах расчёта](main-web/tests/engine.test.cjs) и [тестах приёмки](main-web/tests/acceptance.test.cjs); такие же наборы есть в main-windows.

| Требование | Что должно подтвердиться |
| --- | --- |
| Все источники участвуют в базовой потребности | Изменение истории, остатков, своевременных поставок, категории и планового прироста влияет на результат в контрольных сценариях |
| Сезонность и устойчивый рост | Сезонный пик отражается в прогнозе; устойчивая тенденция меняет прогноз относительно постоянного спроса |
| Упущенный спрос при stockout | Компенсация повышает оценку спроса относительно расчёта по фактическим продажам |
| Разовые крупные заказы | Добавленная покупка 10 000 единиц одним клиентом не вызывает сопоставимого роста регулярной потребности |
| Заказы по поставщикам с объяснением | Рекомендации имеют обоснования; интерфейс группирует заказы и позволяет проверить их перед утверждением |

### Автоматическая проверка

Из корня репозитория:

~~~powershell
npm.cmd --prefix main-web test
npm.cmd --prefix main-web run check:offline
npm.cmd --prefix main-web run build
npm.cmd --prefix main-windows ci
npm.cmd --prefix main-windows test
npm.cmd --prefix main-windows run check:offline
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm.cmd --prefix main-windows run test:desktop
~~~

Ожидаемый результат: все команды завершаются без ошибок; npm test сообщает **72 успешные проверки для каждой версии**, а test:desktop — **58 проверок в работающем Windows-приложении**. Веб-сборка создаёт папку main-web/_site. Зафиксированные результаты и ограничения проверки версии 1.1: [Web](main-web/docs/VERIFICATION.md), [Windows](main-windows/docs/VERIFICATION.md).

Проверки охватывают расчёт, формат проекта, сценарии ТЗ, безопасность путей и ресурсов, упаковку веб-сайта и Electron. Проверка Windows дополнительно открывает приложение и выполняет сценарии интерфейса. Изменения общих файлов assets необходимо переносить в обе версии и проверять отдельно: это две самостоятельные копии кода без символьных ссылок.

GitHub workflows подготовлены в репозитории. Их выполнение в вашем GitHub начинается после загрузки кода и включения нужных возможностей.

## Данные и ограничения

Импорт должен поступать из согласованной обезличенной выгрузки. Распознанные клиентские поля заменяются локальными HMAC-SHA256 идентификаторами до расчёта; неизвестные текстовые поля могут содержать чувствительную информацию. Рабочие проекты и экспорт содержат коммерческие показатели и не зашифрованы приложением.

Файлы .pfproject сохраняют нормализованные данные и журнал, без исходных листов. Журнал является локальной историей действий, не электронной подписью и не системой разграничения доступа. Не загружайте рабочие проекты и выгрузки на GitHub.

Неизвестный остаток не равен нулю. Точность рекомендаций зависит от полноты остатков, сроков поставки, клиентских идентификаторов и периодов stockout. Экономический эффект и качество прогноза требуют проверки на истории компании. Лимит одного файла/ZIP — 25 МБ, проекта — 80 МБ; XLS, XLSB и зашифрованные книги не поддерживаются.
