# ProcureFlow Desktop 0.2 — Windows + Web

## Что это

Один проект, два способа запуска: сайт GitHub Pages и самостоятельная Windows-программа.
Расчётное ядро `assets/engine.js` общее и не изменено относительно 0.1.
Desktop загружает встроенные файлы, а не опубликованный сайт. После сборки для работы
не нужны интернет, аккаунт, Python, Node.js, установленный Chrome, Microsoft Excel или сервер.
Целевая платформа этой сборки — Windows 10/11, x64. Windows 7/8, 32-bit и нативный ARM64 в неё не входят.
Запуск на Windows в текущей среде не проверен; фактическую совместимость подтверждает тест на целевом ПК.

## Что есть в исходном архиве

Это исходный репозиторий с Windows-оболочкой, а НЕ архив с уже скомпилированными EXE.
В этой среде недоступны Windows и загрузка сборочных пакетов npm / Electron; готовая Windows-сборка
здесь не запускалась. Workflow собирает EXE на Windows-раннере GitHub, затем запускает упакованное
приложение в режиме самопроверки. Только успешный job публикует артефакт приложения.
Статус конкретного запуска смотрите в Actions; наличие исходников не означает успех сборки.

## Получить EXE через GitHub — без установки программ на Mac

1. Распакуйте архив и загрузите его содержимое в существующий репозиторий, заменяя старые файлы.
   `index.html`, `package.json`, папки `assets`, `desktop`, `build`, `scripts`, `tests` — в корне.
2. Убедитесь, что существует `.github/workflows/build-windows.yml`.
   На Mac папка `.github` скрыта: **Command + Shift + .** показывает скрытые файлы.
   Если она не попала в загрузку: в GitHub нажмите **Add file → Create new file**,
   задайте имя `.github/workflows/build-windows.yml`, вставьте содержимое видимого файла
   `BUILD_WINDOWS_WORKFLOW.yml` из архива и нажмите Commit changes.
3. **Actions → Build Windows EXE → Run workflow → main → Run workflow**.
   Workflow также настроен на push в `main` / `master` при изменении файлов приложения.
4. Откройте запуск с зелёной отметкой. Внизу в **Artifacts** скачайте **ProcureFlow-Windows-x64**.
5. Распакуйте скачанный ZIP. Внутри ожидаются:
   - `ProcureFlow-Portable-0.2.0-x64.exe` — самостоятельный запускаемый файл без установки;
   - `ProcureFlow-Setup-0.2.0-x64.exe` — установщик с ярлыком;
   - `SHA256SUMS.txt` — контрольные суммы;
   - `desktop-smoke.json` — результаты самопроверки упакованного приложения;
   - `package-lock.resolved.json` — реально разрешённые версии зависимостей сборки.
6. Передайте менеджеру Portable EXE либо установщик. Исходники и npm ему не нужны.

Артефакты этого workflow хранятся 14 дней. Скачивание требует входа в GitHub и доступа к репозиторию.
Не путайте артефакт EXE со скачиванием исходного репозитория через Code → Download ZIP.
Если workflow красный, откройте упавший шаг: артефакт приложения при неуспешной проверке не выдаётся.

## Как использовать

Запустите Portable или установите Setup. При первом запуске показаны синтетические демоданные,
а не сохранённые данные компании. Нажмите **Загрузить Excel**, выберите свои файлы, проверьте
дату среза и допущения. Используйте рекомендации, карточку «Почему?», сценарий и экспорт как в веб-версии.

**Сохранить проект / Ctrl+S** создаёт локальный `.pfproject`: исходные таблицы, нормализованные
данные, параметры, ручные количества и статусы подтверждения. **Открыть / Ctrl+O** восстанавливает
проект; рекомендации пересчитываются тем же ядром. Историческая дата среза не меняется автоматически.
Пересчёт параметров, как и раньше, сбрасывает ручные количества и подтверждения.

Формат общий для Web и Desktop: можно сохранить проект из браузера и открыть его в Windows,
либо наоборот. Передача файла — ручная; никакой автоматической синхронизации нет.
Не удаляйте скачанный проект, пока не проверили его повторное открытие.

Автосохранение не включено. Перед выходом сохраняйте проект; предупреждение о несохранённых изменениях
не является резервной копией. Сохранение проекта на сайте использует скачивание файла браузером,
в Desktop — системное окно выбора места. Приложение создаёт стандартный локальный профиль Electron
в каталоге пользовательских данных, но не сохраняет туда ваши Excel автоматически.

## Приватность и границы защиты

- Все скрипты, стили, XLSX-парсер, графики и расчёт находятся в пакете. Внешних CDN и AI API нет.
- В интерфейсе действует CSP `connect-src 'none'`; в Electron дополнительно блокируются HTTP(S),
  WebSocket, FTP и произвольные file:// запросы. Внешние окна и навигация запрещены.
- Renderer работает с `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`.
  Разрешены только узкие IPC-команды; проверяется отправитель из основного окна приложения.
- Приложение не отправляет заказы поставщику, телеметрию или отчёты об ошибках; обновление — вручную.
- `.pfproject` — НЕ зашифрованное хранилище. Это JSON с коммерческими данными и исходными листами.
  Пользователь с доступом к файлу может их прочитать / изменить. Не публикуйте такие файлы в GitHub.
  Сохранённый статус подтверждения не является подписью, проверкой личности или журналом аудита.
- Исходные данные клиентов должны быть обезличены до загрузки. Desktop сам по себе их не анонимизирует.
- Сетевой запрет относится к запросам приложения. ОС и защитное ПО могут независимо проверять
  исполняемый файл; приложение не управляет сетевым поведением ОС. Независимого аудита безопасности нет.

## Подпись Windows

Эта MVP-сборка без цифровой подписи издателя. Windows / корпоративная защита может предупредить,
потребовать разрешение или запретить запуск. Не отключайте антивирус и не обходите запреты организации.
Для внедрения согласуйте приложение с IT и подпишите релиз сертификатом издателя. Параметр
`CSC_IDENTITY_AUTO_DISCOVERY=false` в демо-workflow выключает автопоиск сертификата.

## Локальная сборка разработчиком

На Windows с Node.js 22+ и интернетом запустите `BUILD-WINDOWS.cmd`, либо:

```sh
npm install --no-audit --no-fund
npm test
npm run check:offline
npm start
npm run dist:win
```

Результаты — `dist/`. Для последующих воспроизводимых сборок сохраните сгенерированный `package-lock.json`
в репозитории и используйте `npm ci`. Основные инструменты закреплены: Electron 44.4.5,
electron-builder 26.16.1; транзитивные версии разрешаются при первой установке и фиксируются lock-файлом.
Сборка требует интернета, работа конечного приложения — нет. Node.js нужен разработчику, не менеджеру.

## Проверки

`npm test` — расчёт, сериализация проекта, ручные количества, защита от некорректных проектов,
ограничения маршрутизации и статическая конфигурация Electron. Никаких npm-пакетов для этих тестов не нужно.
`npm run check:offline` — отсутствие внешних ресурсов / сетевых API в UI и наличие CSP.
`npm run test:desktop` — настоящая самопроверка Electron при установленном пакете.
Workflow дополнительно запускает `dist/win-unpacked/ProcureFlow.exe --smoke-test`.
Самопроверка не заменяет ручной тест диалогов сохранения, печати / политик защиты на ПК менеджера.

## Демо перед жюри

Отключите сеть на тестовом Windows-ПК. Запустите EXE с закрытым браузером, загрузите те же Excel,
откройте «Почему?», измените параметр сценария и экспортируйте Excel. Сохраните `.pfproject`,
закройте программу и снова откройте сохранённый проект. Это демонстрирует автономность, а не просто
новую иконку для сайта. Не обещайте более точный прогноз лишь из-за наличия EXE: алгоритм общий.
